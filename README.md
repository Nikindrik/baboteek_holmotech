# Прогноз ценности пользователей поиска

Решение задачи прогнозирования суммарной стоимости заказов пользователя на следующие 30 дней по его дневной истории активности в поиске и каталоге.

В репозитории оставлены исследование данных, подготовка признаков, базовая модель, нейросетевые признаки и два финальных решения.

## Структура

```text
notebooks/
├── 00_eda.ipynb
├── 01_prepare_features_nvidia.ipynb
├── 02_base_model.ipynb
├── 03_neural_features.ipynb
├── 04_solution_v26.ipynb
└── 05_solution_v27.ipynb

data/
├── train.parquet
└── sample_submit.csv

artifacts/
README.md
requirements.txt
```

Папки `data/` и `artifacts/` не должны добавляться в репозиторий.  
`data/` содержит исходные данные, а `artifacts/` создаётся автоматически во время работы тетрадей.

## Как запустить

Для полного воспроизведения финальных решений нужна машина с видеокартой NVIDIA и рабочей поддержкой CUDA в PyTorch.

Рекомендуемая версия Python — 3.14.

После клонирования репозитория:

```bash
uv venv
source .venv/bin/activate
uv pip install -r requirements.txt
```

Исходные файлы необходимо положить в папку `data/`:

```text
data/train.parquet
data/sample_submit.csv
```

Также поддерживается название `sample_submission.csv`.

Затем тетради запускаются целиком и строго по порядку:

```text
01_prepare_features_nvidia.ipynb
        ↓
02_base_model.ipynb
        ↓
03_neural_features.ipynb
        ↓
04_solution_v26.ipynb
        ↓
05_solution_v27.ipynb
```

`00_eda.ipynb` содержит исследование данных и для получения финального файла с предсказаниями не требуется.

После каждого этапа необходимые промежуточные результаты сохраняются в `artifacts/`, откуда их автоматически читает следующая тетрадь. Поэтому переносить файлы вручную между этапами не нужно.

Финальные файлы появляются здесь:

```text
artifacts/solution_v26/submission_v26_J065_e96d822fa5.csv
artifacts/solution_v27/submission_V27_172071bcb3.csv
```

## Общая идея решения

Главная сложность задачи в том, что будущая стоимость заказов складывается из нескольких разных вещей:

- будет ли пользователь вообще покупать;
- сколько дней с покупками будет в следующие 30 дней;
- сколько денег в среднем приходится на эти покупки;
- насколько текущее поведение пользователя похоже на его обычное состояние или на новый режим.

Поэтому мы не пытаемся решить всю задачу одной регрессией. Итоговый прогноз собирается из нескольких моделей, каждая из которых отвечает за свою часть.

Сначала из дневной истории пользователя строятся обычные признаки: активность за разные окна времени, покупки, корзины, поиск, давность последнего действия, изменение активности со временем и другие агрегаты.

Отдельно строятся признаки будущего поведенческого состояния. Две нейросетевые модели последовательности прогнозируют активность пользователя на ближайший месяц. Их результаты затем переводятся в более устойчивое описание поведения: вероятность покупок, ожидаемое число активных дней, число дней с заказами и мягкие доли нескольких типичных поведенческих состояний.

Ещё одна нейронная сеть обучается непосредственно на длинной дневной истории и выдаёт компактное числовое представление пользователя. Оно не используется как самостоятельный прогноз стоимости. Его задача — дать моделям дополнительную информацию о форме поведения, которую трудно полностью описать обычными суммами и средними.

После этого основная часть расчёта выполняется градиентным бустингом CatBoost.

## Решение V26

V26 строится вокруг сильной базовой модели, но денежная часть прогноза дополнительно раскладывается на две понятные составляющие.

Первая составляющая оценивает, сколько дней с покупками ожидается у пользователя в будущем месяце. В коде эта часть называется `A`.

Вторая составляющая оценивает денежную интенсивность покупок при таком количестве покупочных дней. В коде эта часть называется `B`.

Таким образом, вместо прямой попытки сразу угадать всю будущую сумму модель отдельно учится понимать частоту покупок и их денежный уровень.

Обе части получают обычные табличные признаки и наиболее полезные компоненты нейросетевого представления пользователя. Для денежной части дополнительно используются признаки последовательности прошлых покупок: наличие истории покупок, разброс их стоимости и прогноз стоимости следующего покупочного дня.

Параллельно сохраняется более консервативный базовый прогноз. Он состоит из:

1. прямого прогноза будущей стоимости по недавней истории;
2. оценки вероятности хотя бы одной покупки;
3. оценки будущей стоимости при условии, что покупки будут.

Новая оценка через частоту и денежную интенсивность не заменяет этот прогноз безусловно. Она используется как поправка к нему.

Если новая модель хочет уменьшить прогноз, поправка применяется полностью. Если она хочет увеличить прогноз, сила повышения ограничивается двумя сигналами: уверенностью в наличии будущей покупки и положением пользователя по величине базового прогноза. Это защищает большую группу пользователей с низкой ожидаемой ценностью от слишком агрессивного завышения.

Именно эта схема формирует итоговый файл V26.

## Решение V27

V27 — не новая модель с нуля, а небольшое развитие V26.

Денежная часть, отвечающая за интенсивность покупок, остаётся той же. Модель стоимости при наличии покупок также сохраняется.

Изменяются три места.

Во-первых, модель ожидаемого числа покупочных дней обучается с немного более консервативной случайностью внутри CatBoost. Это дало более устойчивый вариант той же части решения.

Во-вторых, прогноз по недавней истории смешивается с дополнительной моделью, сильнее ориентированной на последние доступные периоды. Доля новой оценки составляет 45 процентов.

В-третьих, вероятность будущей покупки смешивается с дополнительной моделью вероятности покупки. Доля новой оценки составляет 75 процентов.

После этих замен прогноз снова собирается по той же защищённой схеме, что и V26. Поэтому V27 сохраняет основную архитектуру V26 и меняет только те части, где дополнительная настройка дала улучшение.

## Что делает каждая тетрадь

`00_eda.ipynb` — исследование структуры данных, временных изменений, распределения целевой величины и поведения пользователей.

`01_prepare_features_nvidia.ipynb` — прогноз будущего поведения пользователя по дневной последовательности и построение поведенческих признаков.

`02_base_model.ipynb` — построение основной таблицы признаков и базовой модели, которая используется дальше как опорный прогноз.

`03_neural_features.ipynb` — обучение нейронной сети на дневной истории и сохранение компактного числового представления каждого пользователя.

`04_solution_v26.ipynb` — обучение двух частей денежной модели, объединение их с базовым прогнозом и создание финального файла V26.

`05_solution_v27.ipynb` — точечное обновление нескольких частей V26 и создание финального файла V27.

## Полный порядок запуска

После установки зависимостей и добавления исходных данных в `data/` тетради нужно запускать целиком, сверху вниз.

```text
00_eda.ipynb
```

Этот этап необязателен для получения предсказаний и нужен только для исследования данных.

Основной расчёт выполняется строго в таком порядке:

```text
01_prepare_features_nvidia.ipynb
        ↓
02_base_model.ipynb
        ↓
03_neural_features.ipynb
        ↓
04_solution_v26.ipynb
        ↓
05_solution_v27.ipynb
```

`01_prepare_features_nvidia.ipynb` создаёт поведенческие признаки.

`02_base_model.ipynb` создаёт базовые признаки и промежуточные предсказания.

`03_neural_features.ipynb` создаёт нейросетевое представление пользователей.

`04_solution_v26.ipynb` использует результаты предыдущих этапов и создаёт итоговый файл V26.

`05_solution_v27.ipynb` использует результаты V26, пересчитывает только изменённые части решения и создаёт итоговый файл V27.

Между этапами папку `artifacts/` удалять не нужно: следующая тетрадь использует результаты предыдущей.

## Установка зависимостей

### Через uv

Из корня проекта:

```bash
uv python install 3.14
uv sync
```

После этого тетради нужно запускать в окружении проекта, созданном `uv`.

### Через pip

Сначала создайте и активируйте виртуальное окружение, затем установите PyTorch с поддержкой CUDA 12.6 и остальные зависимости проекта:

```bash
python -m venv .venv
source .venv/bin/activate

python -m pip install --upgrade pip
pip install torch==2.12.1 --index-url https://download.pytorch.org/whl/cu126
pip install .
```

На Windows окружение активируется командой:

```powershell
.venv\Scripts\activate
```
